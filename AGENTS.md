# AGENTS.md — synthroute

> Единая точка входа для любых агентов (Claude Code, Codex, Gemini CLI, Cursor) и людей.
> Подробные правила лежат в `.claude/rules/`: Claude Code подгружает их сам, остальным агентам нужно
> прочитать файлы из индекса ниже перед правкой соответствующих путей.

## Миссия

Пользователь вводит МНН препарата и получает несколько **проверенных** вариантов маршрута синтеза:
со схемой, источниками, статусами проверки и метриками, с правкой через чат и экспортом в HTML/PDF.
Главная идея: **LLM предлагает, детерминированные инструменты доказывают**, и мы измеряем, насколько это лучше
одной LLM без обвязки.

## Инварианты (нарушение любого блокирует мерж)

1. **Проверка до показа.** Ни один факт маршрута не попадает к пользователю без статуса проверки (`TRUST-*`).
2. **Происхождение.** У каждого факта есть источник (DOI, патент, запись ORD и цитата) или пометка «гипотеза модели».
3. **Рамки безопасности.** Работаем только с одобренными препаратами. Входной гейт работает по принципу fail-closed, дисклеймер стоит везде (`SAFE-*`).
4. **Модель меняется конфигом.** Все вызовы LLM идут через один gateway, роли моделей задаются в конфиге (`LLM-*`).
5. **Воспроизводимость.** Любое число в отчёте или статье воспроизводится одной командой на зафиксированном коммите (`EVAL-*`).
6. **Формат маршрута является публичным контрактом.** Он задан JSON Schema и версионируется по SemVer (`SCHEMA-*`).
7. **Секреты не попадают в репозиторий**, логи и фикстуры (`CORE-004`).

## Карта репозитория

```
backend/app/
  api/         FastAPI-роутеры (только транспорт)
  services/    сценарии: generate_routes, edit_route, export
  chem/        обёртки RDKit: чистые функции, без сети
  validation/  проверки → VerificationResult (check_id, version)
  routes/      доменная модель маршрута, метрики, diff версий
  llm/         gateway, роли моделей, кассеты record/replay
  agents/      оркестрация: планировщик, извлечение из литературы
  sources/     адаптеры: PubChem, ORD, AiZynthFinder, Crossref…
  safety/      входной гейт и дисклеймеры
  export/      автономный HTML и PDF
frontend/      Vue 3 + TS + Vue Flow
schemas/route/ JSON Schema формата маршрута + примеры (valid/invalid)
prompts/       версионированные промпты
eval/          бенчмарк, раннер, результаты прогонов
data/          raw (не в git) · fixtures (в git) · карточки датасетов
docs/          adr · rules · research · reports · paper · expert · vision
scripts/       служебные скрипты (check_rules.py и др.)
```

Пока существует только каркас правил и документации. Каталоги кода создаются по мере появления фич.

## Как работать агенту

1. Перед правкой прочитай правила для затрагиваемых путей (см. индекс). Ссылайся на них по ID.
2. Двигайся маленькими шагами: план, затем минимальное изменение, затем проверка (тест или запуск), затем следующий шаг.
3. Если факт не проверен (API, версия библиотеки, химическое утверждение, DOI), не выдумывай его: проверь или явно пометь.
4. Изменилось поведение? Тесты и документация обновляются в том же изменении. Архитектурное решение оформляется как ADR.
5. Не делай commit или push без явной просьбы. Никогда не используй force-push.
6. В конце перечисли, что сделано, чем проверено, что не проверено и какие ID правил затронуты.

## Definition of Done

- [ ] CI зелёный: правила, линтеры, тесты, секреты.
- [ ] Затронутые инварианты соблюдены, ID правил указаны в PR.
- [ ] Если затронут конвейер генерации или проверки, к PR приложен результат `make eval-smoke` с дельтой метрик.
- [ ] Если изменился формат маршрута, есть bump `schema_version`, миграция и примеры.
- [ ] Документация, ADR и глоссарий обновлены.
