# ADR-0001: Правила репозитория оформляются как код

- **Статус:** Предложено
- **Дата:** 2026-10-13
- **Связанные правила:** все

## Контекст
Проект на год делают человек и несколько ИИ-агентов. Правила в свободном тексте не соблюдаются и устаревают.
Критерий защиты 05 требует показать инженерное качество: тесты, CI и обоснование компромиссов.

## Решение
- `AGENTS.md` служит хабом для любых агентов, `CLAUDE.md` импортирует его.
- Правила хранятся в `.claude/rules/**`. Префикс файла задаёт область, `paths:` задаёт, когда файл загружается.
- У каждого правила есть ID, уровень (MUST, SHOULD, MAY), обоснование и механизм проверки. Несделанная автоматизация помечается `[todo]`.
- `scripts/check_rules.py` валидирует структуру и генерирует `docs/rules/REGISTRY.md`. Скрипт запускается в CI, в pre-commit и в хуке Claude Code.
- Нарушения называются по ID в PR, ревью и отчётах.

## Последствия
- Плюсы: правила адресуемы и измеримы (доля автоматизации). Агент получает только релевантные правила для своих путей.
- Минусы: появляется формальность. Чтобы она окупалась, каждую неделю снимаем хотя бы один `[todo]`.
- Дальше: перевод `review`-правил в линтеры (import-linter, тесты схемы).

## Рассмотренные альтернативы
| Вариант | Почему нет |
|---|---|
| Один большой `CLAUDE.md` | раздувает контекст на каждом шаге и не адресуется по ID |
| Только `CONTRIBUTING.md` | агенты его не подгружают автоматически, проверки нет |
| `.cursor/rules` | привязка к одному инструменту; `AGENTS.md` переносим |
