# TRUST — Происхождение и статусы проверки

> Ядро ценности проекта: профессионал должен за секунды понять, чему можно верить. См. ADR-0002.

### TRUST-001 · MUST · Каждый факт маршрута несёт `provenance` и `verification`
- **Почему:** вещество, стадия, условие, выход и метрика без происхождения непроверяемы, а значит бесполезны.
- **Проверка:** auto:schema — поля обязательны в JSON Schema [todo]

### TRUST-002 · MUST · Статус проверки берётся только из закрытого перечня
- **Почему:** перечень единый для бэкенда, UI, экспорта и метрик: `literature` (подтверждено литературой), `computed` (подтверждено расчётом), `hypothesis` (гипотеза модели), `failed` (проверка не пройдена).
- **Проверка:** auto:schema — enum в JSON Schema [todo]

### TRUST-003 · MUST · Статусы `literature` и `computed` выставляет только детерминированный код
- **Почему:** LLM не может подтверждать саму себя. Статусы из её ответа отбрасываются при разборе.
- **Проверка:** auto:test — тест парсера LLM-вывода [todo]

### TRUST-004 · MUST · Ссылка подтверждается, только если источник существует и цитата в нём найдена
- **Почему:** выдуманные DOI и цитаты встречаются у LLM часто. Если DOI не резолвится или цитаты нет в тексте, ставится `hypothesis` и флаг `unverified_citation`.
- **Проверка:** auto:test [todo]

### TRUST-005 · MUST · Результат проверки хранит `check_id`, `check_version` и версии инструментов
- **Почему:** нужно воспроизвести, почему в прошлом месяце стадия считалась валидной.
- **Проверка:** auto:schema [todo]

### TRUST-006 · MUST · Непрошедшее проверку показывается как непрошедшее, а не скрывается и не исправляется молча
- **Почему:** автоисправление допустимо только как новая версия с diff и повторной проверкой.
- **Проверка:** auto:test [todo]

### TRUST-007 · SHOULD · Проверки являются чистыми функциями без сети внутри
- **Почему:** так их можно детерминированно тестировать и кэшировать. Внешние данные приходят через адаптеры `sources/`.
- **Проверка:** review + auto:ci — import-linter запрещает `validation` → `sources` [todo]
