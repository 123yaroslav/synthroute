# SAFE — Рамки применения и безопасность

> Обязательная часть ТЗ. Учебно-исследовательский инструмент для одобренных препаратов, а не руководство по производству.

### SAFE-001 · MUST · Любой запрос проходит входной гейт `safety` до генерации
- **Почему:** платформа работает только для одобренных и зарегистрированных препаратов с известной литературой.
- **Проверка:** auto:test — тест сервиса: без вердикта гейта генерация не запускается [todo]

### SAFE-002 · MUST · Гейт работает по принципу fail-closed
- **Почему:** ошибка, таймаут или неопределённость не должны превращаться в пропуск. Пользователь получает отказ с понятным объяснением.
- **Проверка:** auto:test — тесты на ошибку источника, таймаут и неизвестный ввод [todo]

### SAFE-003 · MUST · Регуляторные перечни хранятся как данные с источником и датой версии
- **Почему:** перечни меняются; хардкод в коде устаревает незаметно. Обновление идёт через PR с ревью.
- **Проверка:** review + auto:ci — у файла перечня есть карточка источника (DATA-001) [todo]

### SAFE-004 · MUST · Дисклеймер присутствует в UI, HTML и PDF
- **Почему:** маршруты не являются подтверждённой технологией. Все стадии требуют экспериментальной проверки квалифицированными специалистами в лицензированных условиях.
- **Проверка:** auto:test — snapshot-тесты экспорта проверяют наличие дисклеймера [todo]

### SAFE-005 · MUST · Патентный статус — справка с источником и датой, без юридических выводов
- **Почему:** платформа не даёт юридических заключений.
- **Проверка:** review

### SAFE-006 · MUST · Агент не ослабляет и не обходит гейт
- **Почему:** «временные» режимы отладки без гейта со временем попадают в прод.
- **Проверка:** agent + review — любые изменения в `backend/app/safety/` требуют ревью человека

### SAFE-007 · SHOULD · Тесты гейта используют нейтральные синтетические фикстуры
- **Почему:** репозиторий публичный; проверять логику гейта можно без содержательных данных о веществах.
- **Проверка:** review
