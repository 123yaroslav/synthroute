# GIT — Ветки, коммиты, PR

> Trunk-based: `main` всегда зелёный и релизопригоден.

### GIT-001 · MUST · Изменения попадают в main только через PR с зелёным CI
- **Почему:** `main` является источником для демо, бенчмарка и статьи.
- **Проверка:** auto:ci — branch protection на GitHub [todo]

### GIT-002 · MUST · Ветки живут коротко и называются по типу работы
- **Почему:** короткие ветки меньше конфликтуют, тип в имени сразу виден в списке PR.
- **Проверка:** review — `feat/…`, `fix/…`, `exp/…` (эксперименты), `docs/…`, `rules/…`, `chore/…`

### GIT-003 · MUST · Коммиты оформляются по Conventional Commits на английском
- **Почему:** из них автоматически собираются CHANGELOG и SemVer-релизы.
- **Проверка:** auto:hook — commit-msg хук в pre-commit; формат `type(scope): summary`, где scope — модуль

### GIT-004 · MUST · Один PR — одна цель; больше ~400 строк значимого диффа нужно делить
- **Почему:** большие PR не ревьюят, а пролистывают.
- **Проверка:** review — lock-файлы и сгенерированные файлы не считаются

### GIT-005 · MUST · PR заполняет шаблон: затронутые ID правил, проверки, eval-дельта
- **Почему:** ревьюер должен понять за минуту, что изменилось и чем это подтверждено.
- **Проверка:** review — `.github/pull_request_template.md`

### GIT-006 · MUST · Агент не делает commit, push и переписывание истории без явной просьбы
- **Почему:** это необратимые или публичные действия.
- **Проверка:** auto:hook + agent — commit и push требуют подтверждения, force-push и `reset --hard` запрещены в `.claude/settings.json`

### GIT-007 · SHOULD · Релизы выпускаются по SemVer с CHANGELOG, собранным из коммитов
- **Почему:** пользователям библиотеки и формата нужна предсказуемость.
- **Проверка:** auto:ci — release-please [todo]
