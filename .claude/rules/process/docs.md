# DOC — Документация, решения, отчёты

> Что не попало в отчёт, для программы не существует. Из отчётов собираются статья и ВКР.

### DOC-001 · MUST · Архитектурные решения оформляются как ADR в `docs/adr/`
- **Почему:** через полгода нужно понимать, почему выбрано X, а не Y. Структура ADR: контекст, решение, последствия, альтернативы.
- **Проверка:** review — навык `/new-adr`

### DOC-002 · MUST · Документация пишется на русском, а код, идентификаторы, коммиты и комментарии — на английском
- **Почему:** документация адресована команде практики, а код — международному open source. Термины берутся из `docs/glossary.md`.
- **Проверка:** review

### DOC-003 · MUST · Каждую неделю публикуется отчёт `docs/reports/YYYY-Www.html` с исходником `.md`
- **Почему:** это требование программы. Строка «не вышло» с причиной обязательна.
- **Проверка:** review — навык `/weekly-report`

### DOC-004 · MUST · Исследовательские заметки содержат источники, а выводы отделены от цитат
- **Почему:** в отраслевом погружении знания модели не принимаются на веру. Для каждого источника указываются DOI или URL и дата доступа.
- **Проверка:** review

### DOC-005 · SHOULD · Вопросы эксперту копятся в `docs/expert/questions.md` вместе с контекстом и нашей гипотезой
- **Почему:** к эксперту приходят с подготовленными вопросами, а не вместо исследования.
- **Проверка:** review

### DOC-006 · SHOULD · README работает как витрина
- **Почему:** первые 10 секунд решают, поставит ли посетитель звезду. В README нужны демо-GIF, quickstart в одну команду, статус, ограничения и цитирование.
- **Проверка:** review
