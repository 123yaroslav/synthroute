# PY — Python-бэкенд

> FastAPI + Uvicorn, SQLite (async), RDKit, Pydantic v2. Зависимостями управляет uv.

### PY-001 · MUST · Зависимости добавляются только через `uv add`, lock-файл коммитится
- **Почему:** воспроизводимое окружение нужно и для CI, и для статьи.
- **Проверка:** auto:ci — `uv sync --locked` [todo]

### PY-002 · MUST · Код проходит ruff (lint + format) и строгий тайпчек в доменных модулях
- **Почему:** в `chem/`, `validation/` и `routes/` ошибка типа означает неверный маршрут.
- **Проверка:** auto:ci + auto:hook — ruff в pre-commit и CI, mypy strict в CI [todo]

### PY-003 · MUST · На всех границах (API, LLM-вывод, адаптеры) стоят модели Pydantic v2 с `extra="forbid"`
- **Почему:** лишние или пропущенные поля должны падать на границе, а не в глубине системы.
- **Проверка:** auto:test [todo]

### PY-004 · MUST · Слои импортируются только сверху вниз: `api` → `services` → домен
- **Почему:** домен (`chem`, `validation`, `routes`) не знает про HTTP и LLM, поэтому его можно заменять и тестировать отдельно.
- **Проверка:** auto:ci — import-linter [todo]

### PY-005 · MUST · Один пул БД на процесс; тяжёлые синхронные операции выносятся из event loop
- **Почему:** один синхронный вызов RDKit на большом наборе или рендер PDF блокирует весь сервер.
- **Проверка:** review — `anyio.to_thread` или пул процессов

### PY-006 · MUST · Внешние источники вызываются через адаптер с таймаутом, ретраями, кэшем и явной ошибкой
- **Почему:** сеть ненадёжна. Лучше упасть громко, чем тихо испортить маршрут.
- **Проверка:** auto:test — тесты адаптеров на таймаут и 5xx [todo]

### PY-007 · SHOULD · Логи структурированные (JSON) и содержат `run_id`
- **Почему:** трассировка прогона нужна для отладки и для метрик стоимости. Секреты в логи не пишутся, полные промпты пишутся только на DEBUG.
- **Проверка:** review

### PY-008 · MUST · У каждой проверки из `validation/` есть позитивный, негативный и граничный тест
- **Почему:** слой проверки является продуктом. Его ошибки напрямую искажают главную метрику.
- **Проверка:** auto:ci — порог покрытия для `validation/` ≥ 90% [todo]
